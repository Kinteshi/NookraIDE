# Android and AVF deployment

## Build the Tauri Android app

Install the Tauri v2 Android prerequisites first: JDK 17+, Android SDK/NDK, and the Android Rust targets. The generated project currently compiles against Android API 37 and the ARM64 build uses NDK 27.0.12077973. Set `JAVA_HOME`, `ANDROID_HOME` (or `ANDROID_SDK_ROOT`), and `ANDROID_NDK_HOME` to the installed toolchains.

From the repository root:

```sh
pnpm --filter @avf-studio/studio-ui android:init
pnpm --filter @avf-studio/studio-ui android:dev
pnpm --filter @avf-studio/studio-ui android:build
```

`android:init` generates the native project and patches its `MainActivity` with `android:resizeableActivity="true"` for tablet and desktop-window resizing. It also configures Android Network Security Config to allow cleartext only to `127.0.0.1` (the daemon WebSocket) and `localhost` (the Vite dev server); cleartext to other hosts remains disabled. The Android dev/build scripts verify these generated settings before invoking Tauri. If Android Studio regenerates the project, rerun `android:init`.

The release APK from `android:build` is unsigned until a release signing key is configured. For a locally installable ARM64 debug APK, run:

```sh
pnpm --dir apps/studio-ui exec tauri android build --debug --target aarch64 --apk
```

The Android build output is under `apps/studio-ui/src-tauri/gen/android/app/build/outputs/apk/`. Use a private release keystore for distribution; do not commit it to the repository.

For desktop development, use `pnpm --filter @avf-studio/studio-ui tauri:dev` or `tauri:build`. The normal Vite `dev`, `typecheck` and `build` scripts remain available.

## Install the guest daemon

Build `avf-daemon` for the Debian guest architecture and copy the executable into the guest along with the workspace directory. In the guest, run the bootstrap script as the account that will own the workspace and daemon:

```sh
scripts/bootstrap-avf.sh /path/to/avf-daemon /absolute/path/to/workspace
```

The script installs the executable to `~/.local/bin/avf-daemon`, creates a 256-bit hexadecimal token at `~/.config/avf-studio/token` if one does not already exist, enforces mode `0600`, and enables a user systemd service. It does not overwrite a valid existing token. The configured workspace must already exist; the daemon only exposes that workspace to the VFS.

Check the user service with `systemctl --user status avf-studio.service`. The account needs an active systemd user manager; enable lingering with the guest administrator if the service must start before that account logs in. Open the token file locally in the guest to transfer its value to AVF Studio. Do not put the token in a URL, source file, or command-line argument.

The daemon binds to loopback port `19860`; AVF's host-to-guest port forwarding must expose it to the Android host. The default Origin allowlist includes Tauri's local origin. Development browser origins remain enabled only in debug daemon builds.

## Local validation limits

The Android project and manifest are generated by `tauri android init`. Frontend checks and Tauri CLI configuration inspection do not need the Android toolchain. Android project generation/APK builds require the JDK and Android SDK/NDK; Linux desktop Tauri builds additionally require the WebKitGTK and librsvg development libraries. This repository's ARM64 release APK was built locally, but device runtime testing still requires an attached Android device or emulator.
